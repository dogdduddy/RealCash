# requires-review: wallet.open.c
[목적] 열린 지갑 화면의 시점을 다시 바꾼다(사용자 결정 2026-11-05, docs/04 §9). 검은 반지갑을 바닥에 눕혀 펼친 모습을 위에서 내려다보고, 지갑은 세로로 화면 왼쪽에, 지폐는 오른쪽 가장자리의 지폐 칸 입구에서 오른쪽으로 빠져나와 눕혀져 있다. 지폐는 한 뭉치로 겹쳐 쌓이며 비싼 지폐가 맨 아래·싼 지폐가 맨 위, 빠져나온 폭은 싼 지폐가 가장 넓고 비싼 지폐가 가장 좁다(비싼 돈은 깊이 숨고 잔돈이 앞에 보인다). 지금의 "벌어진 칸 + 원근 띠" 표현은 버린다.

[화면·파일] 열린 지갑. shared/ui/src/commonMain/kotlin/com/jim/realcash/ui/walletopen/ 전부(WalletOpenLayout.kt, WalletOpenScreen.kt, WalletMotion.kt, WalletPhysics.kt, CoinScatter.kt)와 테스트. 홈·접시·집기 고스트·동전 바닥 동작·저장 로직은 유지.

[요청] 열린 지갑 v4 — 눕혀 펼친 지갑, 오른쪽으로 빠져나온 지폐 뭉치
1. 지갑: Res.drawable.wallet_open(교체된 새 그림, 세로가 긴 평면 구도)을 접시 아래 왼쪽에 둔다. 높이는 화면 세로의 약 55%(가로 모드는 접시 오른쪽에 높이 맞춤), 왼쪽 여백 12dp, 잘리지 않게 전체 표시. 지폐 칸 입구는 assets/manifest.json 의 wallet.open.c.opening (openingXFraction = 입구 세로선의 x 비율, topFraction/bottomFraction = 입구 세로 범위) 를 상수로.
2. 지폐: 긴 변이 세로(지갑 긴 축과 평행), 눕혀진 앞면 그대로(원근·회전 없음, 세로로 세운 그림은 지금처럼 rotationZ 90 으로 돌리되 숫자가 읽히는 방향). 길이는 지갑 높이의 약 0.8 × (권종 실제 비율: 오만원이 가장 길다). 지폐의 왼쪽 부분은 칸 안에 있어 입구 x 왼쪽으로는 그리지 않는다(clipRect). 오른쪽으로 빠져나온 폭(짧은 변 기준): 천원 55%, 오천원 45%, 만원 35%, 오만원 25%.
3. 쌓기: 한 뭉치. 그리기 순서는 오만원(맨 아래)→만원→오천원→천원(맨 위). 아래 장일수록 위쪽 끝이 14dp 씩 더 위로 가게 세로로 어긋나게 두어(사진의 계단식 머리) 각 권종의 위쪽 끝이 보이게 한다. 같은 권종 여러 장은 1.5dp 씩 오른쪽·아래로 어긋난 얇은 묶음으로, 총 어긋남은 12dp 까지(장수가 많으면 간격을 줄인다). 뒤 장일수록 살짝 어둡게.
4. 집기: 각 권종의 "보이는 부분"(위쪽 끝 머리 + 맨 위 권종은 빠져나온 면 전체)을 길게 누르면 그 권종의 앞장이 집힌다. 집는 히트 영역은 보이는 부분에 세로로 8dp 여유. 고스트·크기·접시 놓기·복귀는 지금 그대로(집은 지폐 크기는 실물 길이 유지). 집으면 그 장이 빠지고 나머지는 제자리.
5. 흔들림: 빠져나온 지폐 위를 가로로 훑으면 손가락이 닿은 장이 빠져나오는 방향(오른쪽)으로 최대 8dp 밀렸다가 0.35/420 스프링으로 복귀(현재 BillSway 의 displacement 모델 재사용, rotationX 변화는 없음). 왼쪽으로 훑으면 칸 안으로 2dp 까지만. 틱 햅틱은 장을 가로지를 때 1회.
6. 동전: 지갑 오른쪽 바닥 중 지폐가 없는 아래쪽 영역에 흩뿌린다(지폐와 겹치지 않게). 바닥 어디든 놓으면 머무는 동작·접시·복귀는 지금 그대로.
7. 접시, 계산 버튼, 머리글, 안내 문구 위치는 유지. 세로 390×844 와 320×568, 가로 844×390 에서 지갑·지폐·동전이 화면 안에 들어간다.
