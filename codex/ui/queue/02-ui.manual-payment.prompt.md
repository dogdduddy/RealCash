# requires-review: ui.coin-art
[목적] 결제 알림이 잡히지 않았을 때(파서 미지원 앱, 권한 꺼짐, 현금 결제 등) 사용자가 결제를 직접 기록해 정산할 수 있게 한다. 지금은 알림이 와야만 정산이 되고 수동 폴백이 없다. HardPay 에 있던 "직접 입력" 폴백을 RealCash 에 되살리는 작업이다.

[화면·파일] shared/ui 안에서만 작업한다. wallet/WalletHomeScreen.kt 와 WalletHomeModel.kt(손에 든 돈 카드와 지갑 섹션), 새 파일 manual/ManualPaymentSheet.kt + ManualPaymentModel.kt(+ 순수 상태 클래스와 테스트), AppState.kt(시트 상태), Strings.kt. 데이터 API: RealCashData.ids(IdGenerator, `data.ids.next()` 로 문자열 id 생성 — 실제 메서드명은 shared/data 의 util/IdGenerator 를 읽고 맞춘다), WalletRepository.recordDetectedPayment(DetectedPayment), WalletRepository.settle(paymentId, policy, manual = true), SettingsRepository 의 pullPolicy. DetectedPayment 는 domain/model/Payment.kt 참고(sourceApp 은 "manual", rawText 는 빈 문자열, confidence 1f, isRefund false, detectedAt 은 clock.now()).

[요청] 결제 직접 기록 시트 — 금액·가맹점 입력으로 즉시 정산
1. 지갑 홈의 손에 든 돈 카드(손이 있을 때·없을 때 모두)에 "직접 기록" 보조 버튼을 넣는다. 누르면 Material3 ModalBottomSheet 가 열린다.
2. 시트: 금액(원, 천 단위 구분 표시, 기존 AmountInput/ThousandsSeparatorTransformation 재사용), 가맹점(선택), 그리고 "정산하기" 버튼. 손에 든 돈이 있으면 "손에 든 ₩x 로 정산됩니다", 없으면 "지갑에서 자동으로 꺼냅니다(큰 권종부터)" 안내 한 줄.
3. 정산하기: recordDetectedPayment → settle(id, settings.pullPolicy, manual = true) 를 순서대로 호출하고, 결과(낸 돈·거스름돈·플래그 배지)를 시트 안에 표시한 뒤 닫기 버튼. 실패는 스낵바.
4. 시트 상태는 순수 클래스(ManualPaymentDraft: 금액 파싱·검증, 가맹점, 결과)로 두고 단위 테스트를 쓴다(빈 금액·0원·10원 단위 아님 → 비활성, 정상 → 활성).
5. 스크린샷 (p) 시트가 열린 상태(금액 6,500 입력, 손에 든 돈 10,000 있을 때)와 (q) 정산 결과 표시 상태를 추가한다.

[완료 기준] ./gradlew :shared:ui:jvmTest 통과. 시뮬레이터 없이도 "직접 기록"으로 결제가 정산되고 가계부에 MANUAL 배지로 나타난다. 기존 화면 테스트 그대로 통과.

[비교] 확인 시트 confirm/ConfirmPaymentsSheet.kt 의 결과 표시 방식을 따른다.
