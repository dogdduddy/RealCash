# requires-review: ui.wallet-open-physics
[목적] 열린 지갑 제스처가 저장·재배치 중에도 끊기지 않게 한다. 지금은 Modifier.walletGestures 의 pointerInput 키에 enabled(= !submitting)와 sway 리스트가 들어 있어, 접시에 놓고 300ms 뒤 저장이 시작되거나 포켓 묶음이 재배치되면 pointerInput 이 재시작되고, 그 순간 누르고 있던 다음 지폐의 롱프레스가 사라진다(손을 뗐다 다시 눌러야 집힌다). 또 WalletOpenModel.setOnTray 는 submitting 중 들어온 선택을 버려서, 고스트는 접시로 날아갔는데 돈은 포켓에 남는 불일치가 난다.

[화면·파일] 열린 지갑. shared/ui/src/commonMain/kotlin/com/jim/realcash/ui/walletopen/WalletMotion.kt, WalletOpenScreen.kt, WalletOpenModel.kt 와 shared/ui/src/jvmTest/kotlin/com/jim/realcash/ui/walletopen/ 의 테스트.

[요청] 열린 지갑 제스처가 저장·재배치 중에도 끊기지 않게
1. walletGestures 의 pointerInput 키는 physics 와 density 만 남긴다. enabled·pocket·hits·sway 는 rememberUpdatedState 로 감싼 State/람다로 블록 안에서 읽는다. enabled 가 false 인 동안은 새 down 만 무시하고, 이미 진행 중인 롱프레스·드래그·흔들림은 끝까지 처리한다.
2. WalletOpenModel.setOnTray 는 submitting 중에도 선택을 버리지 않는다: choices 와 trayOrder 에 반영해 두고 진행 중인 저장이 끝나면 다시 저장한다. save() 의 finally 가 그 사이 들어온 선택을 지우지 않아야 한다. 결과적으로 마지막 접시 내용 = activeHand.
3. 테스트: (a) ImageComposeScene — 지폐 하나를 접시에 놓고 100ms 뒤 다른 지폐를 누르기 시작해 400ms 유지하면, 300ms 시점의 저장이 중간에 끼어도 physics.picked 가 그 지폐다. (b) WalletOpenModel 단위 테스트 — 저장이 진행 중일 때(FailingIds 류로 느리게 만들거나 디스패처 제어) setOnTray 가 들어오면 최종 activeHand 에 반영된다. (c) 기존 WalletOpenSwayTest 의 "스프링 프레임은 리컴포지션 없음" 조건을 유지.

[완료 기준] ./gradlew :shared:ui:jvmTest 통과(기존 125개 + 새 테스트). 검수용 스크린샷 (w2) 집은 직후 상태를 shared/ui/screenshots/w2-wallet-open-held.png 에 1x 밀도(390×844)로 저장해 커밋한다(테스트는 realcash.screenshotDir 에 쓰고 사본만 복사).
