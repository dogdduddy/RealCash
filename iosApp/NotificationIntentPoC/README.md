# NotificationIntentPoC — iOS 27 알림 트리거 → App Intent 검증 앱

iOS 27 단축어의 **"알림 수신 시"** 자동화가 결제 알림의 제목/본문/앱 이름을 우리 앱의 App Intent 로 넘겨줄 수 있는지 실기기에서 확인하기 위한 최소 앱이다. 동시에 **iOS 알림 샘플 수집기** 역할도 한다. 받은 내용은 기기 안에만 저장되고, JSON 으로 내보내 파서 규칙 작성에 쓴다.

- 앱 최소 버전: iOS 17.0 (App Intents 안정 버전). 알림 트리거 자체는 iOS 27 에서만 존재한다.
- iOS 27 전용 부분은 **전부 단축어 앱 설정** 이고 코드에는 없다. 코드는 iOS 16/17 시절의 App Intents, SwiftUI, `UserDefaults` 만 쓴다.
- 서드파티 의존성 없음. 서버 전송 없음.

## 구성

| 파일 | 역할 |
|---|---|
| `project.yml` | XcodeGen 스펙 (번들 ID `com.jim.realcash.poc`, iOS 17.0, SwiftUI) |
| `Sources/PoCApp.swift` | `@main` 앱 진입점 |
| `Sources/RecordNotificationIntent.swift` | App Intent **"결제 알림 기록"** + `AppShortcutsProvider` |
| `Sources/NotificationStore.swift` | 기록 모델(`Codable`), `UserDefaults` 저장, `clear()`, `exportJSON()` |
| `Sources/ContentView.swift` | 기록 목록, 개수, 내보내기/복사/테스트 기록/모두 삭제 |

### App Intent 파라미터

단축어에서 "결제 알림 기록" 동작을 추가하면 아래 파라미터가 보인다. 전부 선택(optional)이다.

| 단축어 표시 | 코드 프로퍼티 | 타입 | 무엇을 연결하나 |
|---|---|---|---|
| 제목 | `notificationTitle` | 텍스트 | 알림 제목 |
| 부제목 | `notificationSubtitle` | 텍스트 | 알림 부제목 (있으면) |
| 본문 | `notificationBody` | 텍스트 | 알림 본문 |
| 앱 이름 | `sourceApp` | 텍스트 | 알림을 보낸 앱 |
| 알림 시각 | `postedAt` | 날짜 | 알림 수신 시각 (단축어가 제공하면). 연결하면 앱이 지연 시간을 자동 계산한다 |

앱은 백그라운드에서 실행되고(`openAppWhenRun = false`) 기록 후 "RealCash PoC: ○○ 알림 기록됨 (총 N건)" 대화 결과를 돌려준다. 값은 받은 그대로 저장한다. 목록에서 `(없음)` 은 값이 안 넘어온 것, `(빈 문자열)` 은 빈 값이 넘어온 것이다.

## 1. 빌드 방법

### A. XcodeGen (권장)

```bash
brew install xcodegen          # 최초 1회
cd iosApp/NotificationIntentPoC
xcodegen generate              # NotificationIntentPoC.xcodeproj 생성
open NotificationIntentPoC.xcodeproj
```

생성된 `.xcodeproj` 는 빌드 산출물이므로 커밋하지 않는다.

### B. 수동 (XcodeGen 없이)

1. Xcode → File → New → Project → iOS → **App**. Interface: SwiftUI, Language: Swift, Storage: None, 테스트 체크 해제.
2. Product Name 은 아무거나(예: `NotificationIntentPoC`), Bundle Identifier 는 `com.jim.realcash.poc` (개인 팀에서 이미 쓰인 ID 라고 나오면 뒤에 아무 접미사를 붙여도 된다).
3. 템플릿이 만든 `<이름>App.swift` 와 `ContentView.swift` 를 삭제한다(Move to Trash). 둘 다 지우지 않으면 `@main` 과 `ContentView` 가 중복되어 빌드가 실패한다.
4. 이 폴더의 `Sources/` 를 프로젝트 네비게이터로 드래그 → "Copy items if needed" 해제, "Create groups", 타깃 체크.
5. 타깃 → General → Minimum Deployments 를 **iOS 17.0** 으로.
6. (선택) 타깃 → Info 에 `Bundle display name` = `RealCash PoC`.

### 서명

- 타깃 → Signing & Capabilities → **Automatically manage signing** 켜고 Team 선택. 무료 개인 팀(Personal Team)으로 충분하다. (`project.yml` 의 `DEVELOPMENT_TEAM` 에 팀 ID 를 적어 두면 매번 고를 필요가 없다.)
- 무료 팀은 설치 후 7일이 지나면 앱이 실행되지 않으니 다시 빌드해서 설치한다.
- 기기에서 처음 실행할 때 설정 → 일반 → VPN 및 기기 관리 에서 개발자 앱을 신뢰해야 할 수 있다. iOS 16 이상은 설정 → 개인정보 보호 및 보안 → **개발자 모드** 도 켜야 한다.
- 추가 Capability(App Groups 등)는 필요 없다.

### 설치 후 첫 확인

1. 앱을 한 번 실행한다. ("테스트 기록 추가" 를 눌러 목록·내보내기가 동작하는지 본다.)
2. 단축어 앱 → 단축어 탭 하단(또는 앱 목록)에 **RealCash PoC → 결제 알림 기록** 이 보이는지 확인한다. 안 보이면 앱을 한 번 더 실행하거나 기기를 재시동한다.
3. 단축어 앱에서 "결제 알림 기록" 을 직접 실행해 보고, 앱 목록에 `단축어 경유` 기록이 추가되는지 확인한다. 여기까지 되면 App Intent 자체는 정상이다.

## 2. iOS 27 단축어 자동화 설정

> iOS 27 은 새 OS 라서 아래 메뉴 이름은 실제와 조금 다를 수 있다. **다른 부분은 그대로 적어서** 3장 체크리스트의 "메모" 칸에 남겨 주세요. (예: "알림 수신 시" 가 실제로는 "알림" 또는 "앱 알림을 받을 때" 였다 등)

1. **단축어** 앱 → 하단 **자동화** 탭 → 오른쪽 위 **+** (또는 "새로운 자동화").
2. 트리거 목록에서 **"알림 수신 시"** (영문 UI 라면 "Notification" / "When I receive a notification" 비슷한 항목)를 고른다.
3. **앱 선택**: 결제 알림을 보내는 앱을 고른다. 1차 대상은 **토스**, 그다음 사용 중인 **카드사 앱**(신한 SOL페이, 현대카드, KB Pay 등). 앱마다 자동화를 따로 만들거나, 여러 앱 선택이 되면 한 번에 고른다. 어느 쪽이 가능했는지 메모.
4. (선택) **내용 필터 / 키워드**: "결제" 또는 "승인". 처음에는 **필터 없이** 모든 알림을 받아 보는 것을 권장한다. 결제가 아닌 알림의 형태도 샘플로 필요하고, 필터 조건이 제목·본문 중 어디에 걸리는지도 확인해야 하기 때문이다.
5. 실행 방식: **"즉시 실행"** 선택, **"실행 전에 확인"(Ask Before Running) 끔**. "실행 시 알림" 같은 토글이 있으면 끈 상태와 켠 상태를 각각 기록해 둔다.
6. **"잠금 상태에서 실행 허용"** 류의 토글이 있으면 켠다. (없으면 없다고 메모)
7. 다음 → 동작 추가 → 검색에 "결제 알림 기록" 또는 "RealCash" → **결제 알림 기록** 선택.
8. 동작의 파라미터 칸(제목/부제목/본문/앱 이름/알림 시각)에 **매직 변수** 를 연결한다.
   - 파라미터 칸을 탭 → 키보드 위 변수 막대에서 **"단축어 입력"**(또는 트리거 이름의 변수, 예: "알림") 선택.
   - 넣은 변수 토큰을 다시 탭하면 속성 목록이 나온다. 여기서 각각 **제목 / 본문 / 앱(앱 이름) / 날짜** 를 고른다. 부제목 속성이 있으면 부제목에.
   - 속성 목록이 안 나오고 알림이 통째로만 넘어오면: **본문** 칸에 "단축어 입력" 을 통째로 넣는다. 텍스트로 변환된 결과가 저장되니 어떤 형태로 들어오는지 확인할 수 있다.
   - "앱" 속성이 없으면 **앱 이름** 칸에 직접 "토스" 처럼 고정 텍스트를 입력한다(자동화를 앱별로 만든 경우).
9. **완료** 로 저장.

설정이 끝나면 실제로 결제(소액 결제나 토스 송금 알림 등)를 해서 알림을 받아 본다. 결제가 어렵다면 해당 앱에서 오는 아무 알림으로 먼저 트리거 동작만 확인한다.

## 4. JSON 내보내기와 저장소 반영

1. 앱 → **도구 → 내보내기 (JSON)** → 공유 시트에서 AirDrop / "파일에 저장" / 메일 등 선택. 파일 이름은 `realcash-ios-notifications-YYYYMMDD-HHmmss.json`.
   - 공유 시트가 불편하면 **JSON 클립보드에 복사** 후 메모 앱이나 메신저에 붙여 넣어도 된다.
2. 나중에 저장소의 `docs/samples/ios/` 아래에 넣는다(이 디렉터리는 아직 없음, 리드가 만든다). 파일 이름 예: `docs/samples/ios/2026-11-xx-toss-iphone16.json`. Android 쪽 샘플과 같은 앱·같은 문구인지 비교하는 데 쓴다.
3. **개인정보 주의**: 커밋하기 전에 카드 번호 뒷자리, 이름, 계좌번호 등은 마스킹한다(금액·가맹점·문구 형태는 파서 작성에 필요하므로 유지). 결제가 아닌 개인 알림이 섞여 있으면 해당 레코드를 지운다.

JSON 형태:

```json
{
  "count" : 1,
  "exportedAt" : "2026-11-10T12:34:56.789+09:00",
  "osVersion" : "Version 27.1 (Build ...)",
  "platform" : "ios",
  "records" : [
    {
      "body" : "...",
      "id" : "UUID",
      "origin" : "shortcut",
      "postedAt" : "2026-11-10T12:34:50.100+09:00",
      "receivedAt" : "2026-11-10T12:34:52.300+09:00",
      "sourceApp" : "토스",
      "title" : "..."
    }
  ],
  "schemaVersion" : 1
}
```

(`origin` 이 `manualTest` 인 레코드는 앱의 테스트 버튼으로 만든 것이므로 샘플에서 제외한다. 값이 넘어오지 않은(nil) 필드는 키 자체가 빠진다. 빈 문자열로 넘어온 필드는 `""` 로 남는다.)

## 5. 알려진 미확인 사항과 폴백

**미확인 (이 PoC 로 확인할 것)**
- 알림 트리거가 제목/본문/앱을 **개별 속성** 으로 주는지, 알림 전체를 하나의 값으로만 주는지.
- 잠금 상태·집중 모드·저전력 모드에서의 실행 여부와 지연 시간.
- "즉시 실행" 자동화가 실행될 때 iOS 가 사용자에게 배너를 띄우는지(띄운다면 매 결제마다 보이는 소음이 됨).
- 토스·카드사 앱 알림 문구에 금액과 가맹점이 들어 있는지. 일부 앱은 "결제 알림이 도착했어요" 처럼 내용 없는 알림을 보낼 수 있다.
- 사용자가 자동화를 끄거나 지워도 앱은 알 수 없다. 제품에서는 "최근 N일 감지 없음" 휴리스틱으로 재설정을 안내할 계획이다.
- 앱 이름이 기기 언어(한국어/영어)에 따라 다른 문자열로 오는지.

**폴백**
- **iOS 26 이하**: "알림 수신 시" 트리거가 없다 → 자동 감지 불가. 제품에서는 **수동 입력** 과 **공유 시트**(결제 앱 영수증 화면 공유)로 동작한다.
- **iOS 17+ "거래(Transaction)" 트리거**: 애플페이(Wallet) 결제에서만 동작하고 오프라인 단말 탭 결제 위주다. 한국에서는 사실상 **현대카드 애플페이** 사용자에게만 해당한다. 보조 경로로만 취급한다. (이 앱의 "결제 알림 기록" 동작을 거래 트리거에도 연결해 볼 수 있다. 가맹점·금액을 제목/본문 칸에 연결하면 같은 방식으로 기록된다.)
- iOS 27 경로가 불가능으로 판명되면 iOS 는 수동/공유 시트 모드만 제공하고 자동 감지는 Android 전용 기능이 된다.
